# キャラクター(アバター)機能 計画(PLAN ONLY)

- 状態: 計画ドラフト。実装・依存追加・アセット導入の承認ではない。
- 日付: 2026-11-01
- 参照: [Open-LLM-VTuber](https://github.com/Open-LLM-VTuber/Open-LLM-VTuber)(Live2D + ASR + TTS + デスクトップペット)
- 対象: 既存の `companion_harness`(Svelte web UI + ローカル llama.cpp + 音声レンダラ)に、キャラクター表示・発話・口パクを足す。

## 0. 目的と非目標

目的:
- 回答を「春琴」の見た目と声で提示する。テキスト/記憶/ツール/承認ゲートは現行のまま。
- ローカル完結(クラウドTTS/ASRなし)。プライバシーとオフライン性を維持する。

非目標(今回のスコープ外):
- Open-LLM-VTuber のフォーク、デスクトップペット(透過ウィンドウ)、常時マイク常駐。
- 音声による割り込み(発話中のバージイン)と VAD の本格実装。
- アバター素材の同梱・配布。モデルはユーザーが用意する。

## 1. 参照プロダクトとの差分

| 機能 | Open-LLM-VTuber | 本リポジトリ現状 |
|---|---|---|
| 対話 | 音声中心(ASR→LLM→TTS) | テキスト中心(SSE、ツール、記憶、承認) |
| ペルソナ | キャラYAML + プロンプト | 固定システムプロンプト + 音声プロファイル(京ことば) |
| 音声出力 | TTS(複数) | なし(テキスト書き換えのみ) |
| アバター | Live2D + 表情 + 口パク | なし |
| 音声入力 | ASR(複数)+割り込み | なし |

結論: OLVT をそのままフロントにすると、ツール・記憶・承認ゲート・監査が使えず、二重管理になる。**OLVT は設計の参照元に留め、実装は既存 UI に足す。**

## 2. 方針の比較

### A. OLVT をフロントとして接続(却下)
- companion 側に OpenAI 互換エンドポイントを生やし、OLVT から叩く。
- 長所: Live2D/ASR/TTS が既製。短所: セッション・記憶・試行承認・監査が OLVT 側から見えない。ペルソナも二重定義。デモ用途のみ可。

### B. 既存 web UI に「キャラクター」面を追加(採用)
- サーバ: TTS エンドポイント(補助呼び出し、エージェントループ外)。
- Web: `/character` ルートに Live2D キャンバス + 再生 + 口パク。チャットは既存 SSE のまま。
- 長所: 既存の RunResult(`voice.parts`)をそのまま読める。CSP/認証/監査の枠内。短所: Live2D と TTS の結線は自前。

## 3. 最小スライス(Phase 1)

### 3.1 音声(TTS)は並行トラック(本計画の実装対象外)
音声側は別トラックで実装中。本計画は**消費側(アバター)だけ**を持つ。重複実装しない。

アバターが必要とする最小インターフェース(音声トラックと合意する):
1. 1回答ぶんの音声を取得できる: `POST /api/speech`(または `GET /api/speech/:id`)で `audio/wav`(またはキャッシュURL)。入力は音声レンダリング済みテキスト(`RunResult.voice.parts`)。
2. 認証は既存セッションCookie。SSEには載せない(回答ストリームを阻塞しない)。
3. 失敗時は 4xx/5xx を返し、アバターは無音のまま待機(回答表示は止めない)。
4. 将来の文単位先読みに備え、文ごとに取得できる形が望ましい(最初の版は全文1本で可)。

口パクはフロント側で完結する: 取得した音声を `AudioContext` に接続し、`AnalyserNode` の振幅を `ParamMouthOpenY` に写像する。音声側からタイミング情報を受け取る必要はない。

### 3.2 アバター(Web、VRM)
- モデルは **VRM**(ユーザーが BOOTH で購入した VRChat 用)。Live2D は採用しない。
- 依存: `three` + `@pixiv/three-vrm`(遅延チャンク。CSP のため self 配信、CDN 不可)。
- 新規 `apps/web/src/VrmStage.svelte`:
  - VRM を読み込み、VRM 0.x は 180° 回転して正面を向ける。
  - 口パク: `AudioContext` + `AnalyserNode` の RMS → VRM expression `aa`。音素タイミング不要。
  - 瞬き: 数秒間隔の `blink`。
- `apps/web/src/CharacterPage.svelte` + `CharacterPanel.svelte`:
  - 回答完了時に TTS を取得して再生(音声トラックの契約)。
  - 自動発話 ON/OFF、試聴欄、音声未接続時の案内。
- ルーティング: `routeForPath` に `/character` を追加(サーバ側の feature path も同様)。
- モデル配信: `COMPANION_AVATAR_DIR`(絶対パス)配下の `model.vrm` を `GET /avatar/model.vrm` で配信。`GET /api/character/config` が `{vrmUrl}` を返し、未設定なら SVG のフォールバック表示。
- バンドル予算: 3D チャンクのみ例外(`svelte-app-VrmStage.js` 320KB gz)。他のルートは 120KB のまま。

### 3.3 受入基準(Phase 1)
- `/character` でアバターが表示され、回答完了後に声が出る。
- 口パクが音声の振幅に追従する(無音時に閉じる)。
- TTS 失敗時に回答表示が壊れない。
- ライセンス文書(Live2D SDK / モデル / VOICEVOX)を `docs/` に置く。

## 4. Phase 2(表情・ストリーミング)
- 感情タグ: 回答の `parts` に任意の `emotion` を足し、プロファイルで expression に写像。タグがなければ neutral。
- 文単位 TTS の先読み: 最初の文ができ次第再生し、以降を順次追加。体感遅延を 1〜2 秒に短縮。
- 音声の中断: 新しい回答が来たら再生を止める(`AbortController`)。

## 5. Phase 3(音声入力、任意)
- ASR はローカル必須(Web Speech API はクラウド)。候補: sherpa-onnx(CPU、日本語モデルあり)、whisper.cpp。
- マイク常駐と割り込みは別計画。Phase 1-2 の受入後に判断する。

## 6. リスクとライセンス

| 項目 | リスク | 対応 |
|---|---|---|
| VRM モデル(BOOTH) | 作者ごとの利用規約。再配布不可 | モデルは非同梱、`COMPANION_AVATAR_DIR` でローカル指定のみ |
| VOICEVOX | エンジンと音声ライブラリで規約が異なる | 個人利用の範囲を明記。話者IDは設定で差し替え可能に |
| GPU 競合 | TTS が 35B と VRAM を奪う | TTS は CPU 既定。GPU は明示オプトイン |
| レイテンシ | 回答完了→音声開始が遅い | キャッシュ+文単位先読み(Phase 2) |
| CSP | 外部スクリプト不可 | pixi/live2d をバンドル。`script-src 'self'` を維持 |
| 音声レンダラとの二重化 | 京ことばテキストを TTS が読み上げる | TTS は `voice.parts` を読む。canonical は読まない |

## 7. 見積り(1人)

| Phase | 内容 | 工数 |
|---|---|---|
| 1 | `/character` + VRM ステージ + 口パク | 3〜4日 |
| 1 | 音声トラックとの結線(契約の合意+再生+中断) | 1日 |
| 1 | ライセンス文書・CSP 確認・E2E | 1日 |
| 2 | 表情マッピング + 文単位先読みの消費 | 2〜3日 |
| 3 | ASR(任意) | 5日+ |

## 8. 最初の一歩
1. 音声トラックの担当と `/api/speech` の形(入力・出力・認証・キャッシュ)を合意する(半日)。
2. `/character` に Live2D モデル 1 体を表示し、固定音声で口パクを確認(1〜2日)。
3. 回答完了→音声取得→再生→口パクの結線(1日)。
4. 中断(新しい回答で再生停止)と無音フォールバック(半日)。

**本計画は実装許可ではない。** Phase 1 の着手には、TTS エンジン・アバターモデル・ライセンスの選択への明示的な同意が必要。
